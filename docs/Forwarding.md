# TCP / UDP 转发

## 当前部署方式（v0.2.45 起）

所有新安装和后续转发操作统一使用每台服务器一个共享 GOST 进程，不再显示转发引擎按钮或共享标签。规则仍按监听端口独立管理，单条规则可启停、编辑、删除及统计流量；TCP + UDP 对应两个服务，但共用一个进程。复制规则只保存草稿，安装时自动进入共享服务。

升级主控不会立刻连接并重启所有 VPS。旧独立实例在首次执行安装 / 更新、启停、编辑、删除或检查状态时，先按该服务器的全部规则自动合并，再执行指定操作。首次操作会短暂中断该服务器全部转发连接。可在转发页按服务器或分组执行一键安装 / 更新，顺序处理规则；该按钮会启动已停止的规则，若需保留停止状态，请对一条运行中的规则执行更新来触发迁移。以后同机新增规则直接复用现有进程，无需再次选择。

先更新采集端到 0.2.5 或以上。旧采集端会被阻止执行转发部署，避免混合采样。原规则状态、归属或清单异常会拒绝迁移并提示核对；请先解决旧任务及远端状态。迁移失败尝试恢复旧实例且不继续后续操作；SSH 中断后以实际远端状态和日志为准，不自动退回独立部署新规则。

迁移保留规则 ID 和已保存历史，编辑仍按原有约定生成新规则并清空该规则历史。流量采样与断流窗口不能保证无损补回。删除最后一条已部署规则会停止并禁用共享服务、删除引擎运行状态和配置；备份及程序文件保留，后续安装会自动初始化。API 仍仅监听本机并验证随机密码，共享进程故障会影响该服务器全部规则。

下文早期版本中“手动切换 / 回退”的界面说明仅为历史记录，v0.2.45 已移除该入口。旧规则单进程恢复脚本仅保留用于失败恢复和兼容检查，不作为日常部署方式。


主控左侧的“转发”页面用于管理服务器上的独立 GOST 服务。数据直接经过所选服务器，主控仅通过 SSH 下发配置，不承载转发流量。

1. 在服务器列表填写 SSH 地址、端口、用户名和密码，测试连接并确认服务器指纹。需要 root 或免密 sudo。
2. 在“转发”添加规则，选择服务器、协议、监听端口、目标 IP/域名及端口。
3. 保存后点击“安装”或“更新”，查看日志；停止会取消开机启动，删除会停止并移除对应服务。

例如监听 10161、目标 149.7.2.22:8443、协议 TCP + UDP，生成：

```text
tcp://:10161/149.7.2.22:8443
udp://:10161/149.7.2.22:8443
```

监听所有网卡，未提供加密和客户端身份认证。按实际需要在服务器防火墙、云安全组或 NAT 端口映射中允许对应协议及来源。程序不自动调整防火墙，也不改动已有 GOST 安装。

首版支持 amd64 / arm64，使用 systemd 的 Debian 11+、Ubuntu 22.04+，以及使用 OpenRC 的 Alpine 3.20+。先安装采集端以准备 curl、Python 和系统工具。GOST 固定使用官方 3.3.0 发布文件，下载后按主控内置的官方 SHA256 校验。远程服务器需要能访问 GitHub。安装路径 `/opt/firefly-forward/gost-3.3.0`；每条规则对应 `firefly-forward-规则UUID` 服务。目标支持 IP、IPv6 和域名；监听范围使用 GOST 默认行为，按所有网络接口开放。

状态显示最近一次 SSH 操作的检查结果，点击“检查状态”获取实时服务状态。服务运行不保证目标可达；检查目标服务和防火墙。主控重启后远端服务继续运行。规则配置随主控数据库备份，恢复备份不会自动操作远端服务，需核对状态和遗留规则。停止/删除失败会保留规则，避免将仍在运行的服务隐藏；删除节点或更换 SSH 地址前需先移除转发规则。重新创建同名服务器不会接管旧 UUID 的服务。

手动诊断：`systemctl status firefly-forward-规则UUID --no-pager` 或 `rc-service firefly-forward-规则UUID status`。systemd 日志：`journalctl -u firefly-forward-规则UUID -n 50 --no-pager`。

本功能不依赖插件页面授权，只有登录管理员可操作，写接口需要 CSRF。插件未获得转发接口权限。

GOST 的规则格式参考：[官方命令行文档](https://gost.run/reference/configuration/cmd/)。

## 流量与状态

从 v0.2.18 起，采集端 0.2.2 每 30 秒读取由主控安装的 GOST Metrics。首次使用需要更新采集端，并对已有规则重新点击“安装”或“更新”；会重启该规则的连接。Metrics 只监听 127.0.0.1 的独立端口，不开放管理 API。每次进程启动生成新的统计标识，避免累计计数归零后漏算或重复累计。

每条规则显示 GOST 接收、发送和合计流量，按主控时区的自然月划分，历史保留最近 24 个月。月初切换新月显示，旧月不会删除。主控备份包含规则、计数基线和月份历史。删除规则会删除该规则的流量历史。统计为 GOST 处理字节，不等同于 VPS 网卡计费。无法补录启用前的流量；停止、进程崩溃或跨月时可能存在一个采样间隔的偏差，主控长期离线后的累计按恢复采样时归属月份，不适用于精确跨月对账。

状态灯显示最近的观测结果：绿色表示最近收到实际转发流量；红色表示 SSH 操作失败或采集到 GOST 转发错误；黄色表示服务运行但尚无近期流量验证。未发起请求时，不能据此确认 UDP 目标可达。日志在弹窗内自动更新。

## 每日明细

v0.2.19 将转发地址和流量拆成独立列。列表显示当前自然月累计，点击流量后选择月份查看每日接收、发送和合计，按主控统计时区划日。没有样本的日期不伪造为零流量；升级前仅保存月累计的部分以“升级前未分日”标明。采集端保持 0.2.2，不需要再次更新。

“服务运行 · 待验证”表示服务已启动，但尚未收到近期真实流量验证。通过该规则的入口 IP/端口，使用对应业务客户端发起请求；采集端约每 30 秒采样。只有观察到 GOST 收发字节增量，且近期没有新错误，才会显示绿色转发成功；错误增量会显示红色转发失败。检查状态只检查服务进程，不主动产生业务流量。5 分钟没有新的流量验证，或统计样本超过 90 秒未更新，会回到待验证，不代表服务必然故障。TCP + UDP 合并规则的灯表示汇总观测结果，不能单独证明两个协议或最终业务都可用。

## 规则排序

v0.2.20 支持拖动规则左侧手柄排序，或聚焦手柄后用上下方向键调整。排序按所选服务器独立保存，不重启 GOST，也不改变规则入口或流量记录。

## 编辑并重新部署

v0.2.21 在规则操作中增加“编辑”。可以修改名称、协议、监听端口和目标地址；服务器保持不变。提交前会提示连接中断和流量清零。修改以新服务标识部署，成功后移除原服务，清空该规则的月份、每日历史和统计基线，并保持原排序。旧服务的缓存样本不会重新计入新规则。

部署失败保留原配置和历史，并尝试清理新服务、恢复原服务；恢复也失败时日志会明确说明，需核对服务器状态。中断或失败任务可重新编辑部署或删除规则，重试时会清理上次候选服务。SSH 任务进行中不允许重复编辑。编辑其他服务器需创建新规则。采集端保持 0.2.2。

## 安装、更新与启动按钮

v0.2.22：尚未安装显示“安装”，已安装显示“更新”，更新会重新应用主控提供的 GOST 版本及规则配置并短暂重启连接，不清空流量。运行中显示“停止”，停止后该按钮切换为“启动”；启动沿用现有服务，不重新下载或改写规则。编辑后重新部署仍会清空该规则的历史。编辑日志通过步骤 1/3、2/3、3/3 区分停止原服务、启动新服务、删除原服务文件，最后确认新服务运行。

## 全部转发流量汇总

转发页面顶部显示今日、昨日的全部规则收发合计，单位固定为 GiB，保留两位小数。按主控统计时区的自然日汇总所有服务器，切换服务器不影响汇总；停止的规则仍计入当日已采集流量。数据随采集端上报更新。只有月累计的旧数据不能补算日流量，删除规则或编辑成功清零后，该规则原历史也不再计入汇总。

操作按钮采用图标，鼠标悬停或键盘聚焦显示名称，删除置于最右侧；安装后显示更新，停止后显示启动。“服务运行”表示服务已启动，绿色“转发成功”仍以实际采集到转发流量为依据。

## 转发工作台与批量安装 / 更新

页面顶部显示全部规则数量、异常数量及今日 / 昨日流量。左侧选择服务器，右侧支持规则 / 目标搜索、已启用 / 已停止 / 异常筛选和每页 10 条。转发数量包含未安装规则，已启用表示已安装且未停止，不保证当前服务或目标可达。选择单台服务器、状态为全部且清空搜索时，可拖拽或用方向键调整规则顺序。新增规则在右上角弹窗中添加。

“一键安装/更新”按当前服务器范围处理全部规则，而非仅处理当前搜索或状态筛选结果；确认窗口列出执行范围与数量。规则逐条部署，失败后继续，缺少 SSH 配置、指纹、停用服务器或尚未完成编辑任务的规则会跳过。更新会重新启动服务，包括已停止规则，可能短暂中断连接。确认后可查看进度、实时日志及失败规则；关闭窗口不停止队列。主控重启会中断队列，请核对远端后重新提交。队列执行期间暂停修改规则和启动采集端更新队列，避免交叉部署。

服务器离线仅说明采集端超过主控离线阈值未上报，不代表远端 GOST 已停止。页面将服务器故障与 GOST 转发错误分开显示。最近告警记录保留 50 条，首页只显示最近 3 条，查看全部打开独立窗口。启用前的旧告警不补发。

“告警设置”可以启用转发失败 / 恢复 Telegram 通知，默认关闭。服务器离线 / 恢复沿用原有通知配置，不重复发。转发通知使用“离线 / 恢复”自定义服务器范围，并遵守服务器告警开关、维护状态和静默时间。转发错误以 SSH 失败或 GOST 错误计数为依据，恢复以再次采集到实际流量为依据；服务启动本身不算目标验证成功。

## 将规则复制到其他服务器

点击“复制规则”，选择来源服务器、需要复制的规则和一个或多个目标服务器。新规则保存为未安装状态，包含名称、协议、监听端口、目标地址 / 端口，不继承服务 UUID、运行状态、日志和流量历史，也不会执行 SSH。目标服务器可以暂未配置 SSH。

相同监听端口与重叠协议会跳过，不覆盖已有规则，结果窗口列出原因；达到 200 条总数上限后也会跳过。来源规则部署中不能复制。复制后选择目标服务器，点击编辑调整少数地址或端口，未安装规则“保存修改”只写入配置；确认后再点击安装或一键安装 / 更新。已安装规则编辑仍会重新部署并在成功后清空该规则历史。

服务器列表高度固定，超过高度时滚动。点击“全部服务器”切换到全部规则并收起 / 展开服务器列表，轮询刷新不改变收起状态和滚动位置。

## 转发分组与顶部统计（v0.2.28）

在转发左侧服务器标题旁点击“分组”，新建 / 编辑分组并选择服务器；服务器只属于一个转发分组，移入另一组会从原组移除。分组独立于监控总览和公开页分组。删除分组不会删除服务器和转发规则。下拉框支持全部分组、未分组及自定义分组。批量安装 / 更新按当前服务器或分组执行，确认窗口列出范围，不受规则搜索和状态筛选影响。

左侧“今日流量”显示当前选中服务器所有当前规则的 GOST 实际转发收发合计，未选中时提示先选择服务器。右侧“转发总流量”显示全部服务器当前规则的今日 GOST 流量，副标题注明“全部服务器 · 今日”，不受分组、搜索和规则状态筛选影响。已停止规则当天已记录的流量也计入。

两张卡片点击后打开转发历史，下拉选择最近 15 / 30 / 60 / 90 天，默认 30 天，显示日期范围和期间收发合计。只汇总 GOST 的每日记录，不读取 vnStat 网卡数据、不包含其他程序流量；缺失日期不视为 0。编辑部署成功或删除规则移除其历史后，该规则旧数据不再纳入当前汇总，旧月只有月累计的数据不能补算为日流量。顶部、历史和规则列表使用相同 GOST 数据源。

点击服务器标题旁的“分组”，每个分组名称旁直接显示“编辑”“删除”；编辑可以改名、移入或移出服务器。当前分组会自动载入编辑表单，也可在下方选择“新建分组”。删除只解除分组，不删除服务器和转发规则。

规则表仍为 GOST 应用收发数据，不代表网卡全部流量。跨服务器转发有入口和出口，另有网络协议开销，不能直接将 GOST 接收 + 发送当作网卡上传 + 下载。手动编辑重新部署会清空该规则 GOST 历史，但不会清空网卡历史。点击“流量核对”可对照同一天两种数据及同步状态；统计起点、采样、主控离线也会造成差异。实现基于官方 [GOST 服务统计](https://gost.run/en/concepts/service/) 和 [Metrics](https://gost.run/tutorials/metrics/)，没有对应用数据使用固定倍数换算。

同一进程统计标识下，累计值回退会保留原基线并暂不累加，避免将旧流量重复计入。后续计数恢复后继续增量累计；进程重启且统计标识改变时才从新进程累计值接续。历史已保存的数值不会自动修写。

## 同一时段只读诊断（v0.2.29）

转发页面选中具体服务器 → “流量核对” → “开始 30 秒诊断”。需要先配置 SSH、测试并确认指纹。保持平常的转发访问，诊断不主动下载测试文件，不修改规则或重启服务，不读取 /etc/lightprobe-agent.json。约 30–45 秒后可复制日志；关闭窗口不取消任务，在当前页面可重新打开“查看上次诊断”。主控重启后内存任务记录不保留。

诊断读取两轮本机 GOST Metrics 与 /proc/net/dev，给出同一时段的原始收发增量及网卡上下界，区分当前主控关联规则与远端额外清单，并标记读数缺失、重启、计数回退、Metrics 超过采集端 256 KiB 上限或解析差异，附 TCP 重传段数。自动网卡模式逐张列出，不相加网桥/隧道；无流量的新规则可能尚无字节计数，不必直接判为故障。额外清单可能来自遗留服务，未见清单也可能只是未安装的草稿，需要结合部署情况判断。

网卡计算所有进出接口的字节；GOST 字节计数来自客户端一侧的应用连接，两者范围不同。相同外网网卡承担转发两侧时，其收发总和通常较应用流量更大，但不能只凭固定倍数确认全天统计正确。诊断不能还原过去全天的缺失，也不会修正或清零历史。若差额仍明显，请复制最终诊断日志进一步定位。

## 转发服务器分组排序（v0.2.37）

打开转发页服务器区域的“分组”，在“转发服务器分组”窗口拖动左侧手柄调整顺序，松开后自动保存。手柄获得焦点后也可以用上下方向键调整。分组目录和左侧分组下拉框同步，刷新后保留；“全部分组”和“未分组”保持固定位置。排序不改变分组成员、转发规则和流量历史。仅需更新主控，采集端仍为 0.2.3。

## 跨页排序与大 Metrics 采集修复（v0.2.38 / 采集端 0.2.4）

转发页选择一台服务器，切到“全部”并清空规则搜索后，拖动规则手柄到“上一页”或“下一页”按钮松开，即移到上一页末尾或下一页开头并自动保存；翻页区保持可见。手柄获得焦点后，上下方向键也能跨页排序。不会修改配置或流量历史。

旧采集端对每条规则的 Metrics 响应只读 256 KiB；客户端标签增多后响应会超限，导致整条规则采样不可用、面板偏少。本次改为流式解析（每响应 16 MiB、每行 64 KiB 安全上限），支持标签空格和可选时间戳；遇到读取中断或进程切换拒绝部分样本。点“转发统计不完整 · 查看原因”可查看失败规则。

## 共享 GOST 引擎（v0.2.42 / 采集端 0.2.5）

默认保留原独立进程部署，更新主控不会自动切换。推荐先选择一台机器验证，再逐台迁移。

1. 上传代码并等待 GitHub Check 全部通过，包含真实 GOST 3.3.0 的 TCP / UDP、服务 API、迁移回退和流量隔离检查。
2. 用永久命令更新主控，在服务器列表更新采集端，确认至少 0.2.5。
3. 转发 → 选择服务器 → 转发引擎 → 切换共享进程。需已配置 SSH 并确认主机指纹。
4. 观察切换日志，确认共享模式、规则启停和新流量采样正常，再迁移其他机器。

共享模式每台服务器运行 firefly-forward-engine 一个系统服务，每条规则对应带规则 ID 与代次的独立 GOST 服务。TCP + UDP 规则对应两个服务，仍由一个进程承载。API 只监听 127.0.0.1，并启用随机密码认证；Metrics 只监听本机。凭据与状态保存在 /etc/firefly-forward-engine/，权限 0700 / 0600，不对外开放管理端口。

迁移前核对远端清单、归属和启停状态，拒绝覆盖其他节点的规则。备份位于 /var/backups/firefly-forward/。关闭每个旧实例前记录最后累计样本；先释放一个旧实例再启动引擎，降低切换峰值内存。迁移保留规则 ID、已停止状态与主控已有历史。连接短暂中断，进程退出前后未完成传输的小窗口无法保证无损补回；跨日缺失也不做比例分摊或固定倍数校正。

单条停止、启动或更新只操作对应服务。已保存配置会在共享引擎重启时恢复，进程重启会生成新统计代次。编辑配置仍按原有约定生成新规则并清空该规则历史；仅切换引擎不会清空历史。共享进程故障会影响本机所有规则；减少的是多进程基础开销，连接、缓冲区和指标标签仍会占内存，不承诺具体节省数值。

回退独立进程同样在转发引擎窗口操作，会短暂断流；失败会尝试恢复共享引擎。主控或 SSH 中途断开时，检查日志并重试同一切换方向，或选择回退，不能仅凭失联判断远端已恢复。切换失败请先核对规则状态再操作。共享模式下清除 SSH、换地址或删除节点前，先删除规则并回退独立进程，以免遗留无人管理的引擎。

不能在共享模式直接降级主控或采集端到旧版。必须先回退独立进程；主控会拒收旧采集端在共享模式下的混合计数。旧独立规则服务文件保留用于回退，不要手动启动这些服务与共享引擎争抢端口。

Debian / Ubuntu 检查：systemctl status firefly-forward-engine --no-pager。Alpine 检查：rc-service firefly-forward-engine status。可比较切换前后同等负载下的进程数与内存；RSS 合计不等于独占内存。

端口管理方式不变：例如 10161 → 落地A:8443、10162 → 落地B:443，各端口规则仍分别配置协议、目标、启停及流量统计；合并的是承载这些规则的进程，不合并规则或目标。

## 查看哪些服务器已经共享（v0.2.43）

转发页面左侧每台服务器下方显示引擎模式。“已共享”表示主控记录为共享模式；“独立进程”表示仍按规则独立部署；仅保存草稿但未安装显示“未部署”。切换 / 回退执行中单独显示，失败则显示“需核对”，请进入转发引擎查看日志。

点击“转发引擎”可查看全部转发服务器的模式及数量，点击某台查看详情与操作。已共享后新增规则，安装时自动加入该服务器的共享进程，无需重复切换。引擎模式按服务器保存，更新页面或主控不会清除；这是主控记录的部署模式，不是远端服务的实时健康检查。实际运行状态仍查看规则状态和检查状态日志。

## 现有规则快捷添加中转（v0.2.44）

适用于已经安装的 A → C 规则。在该规则操作区点击“经中转”（分支箭头图标），选择 B 服务器与中转监听端口；中转地址默认取 B 的 SSH 地址，可以改为 A 能访问的实际转发 IP / 域名（NAT 机器不一定与 SSH 地址相同）。C 自动沿用原目标，TCP / UDP 协议也自动沿用。窗口显示 A入口端口 → B中转端口 → C原目标。

1. 点击“第 1 步：安装 / 检查中转”。B 需要已配置 SSH、测试并确认指纹，防火墙需放行选定端口。若 B 上已有协议、监听端口、目标完全相同且运行中的规则，仅检查状态后复用；冲突或未运行的规则不会覆盖。
2. B 确认服务启动后，点击“确认切换入口”。A 的监听端口不变，目标改为 B；沿用现有编辑并重新部署功能。部署会短暂断流，成功后清空该入口规则的月累计及每日流量历史。B 的原有历史（若复用）保留。
3. 完成后实际连接 A 测试端到端可用性。服务启动 / 状态检查只说明本机服务状态，不能证明 A 到 B 到 C 全部网络可达。返回流量自动沿原连接返回，无需创建反向规则。

关闭窗口不会自动开始第 2 步，重新点击原规则的“经中转”可继续。若入口已切换完成，从新的入口规则也能查看完成记录。切换前重新核对入口和中转规则的配置与任务标识，阻止覆盖中途的修改。主控重启后未完成的 SSH 日志若已丢失，会提示中断并要求核对，不自动续跑。

B 失败时不修改 A；A 部署失败时沿用原编辑流程尝试恢复原规则，仍需检查日志与实际状态。放弃任务不会停止或删除已创建的 B 规则，避免影响其他使用者；需要时在 B 的规则列表自行检查、停止或删除。不要将原来指向 A 本机的 localhost / 127.0.0.1 / ::1 目标直接迁到 B，需先使用 B 可访问的落地地址。复杂回环、DNS 别名、网络访问权限仍需自行核对。

规则表中入口显示“经 B → C”，中转显示“中转 → C”；关联规则被修改或删除则提示核对。此路径是配置关系，不是连通性监测。A、B 仍独立管理、启停和统计；同一用户流量会经过两台服务器，汇总不会按链路去重。现阶段提供一次中转的引导，不自动管理整条链路的删除、回退或多级中转。

## 原 VPS 换 IP，保留规则（v0.2.47）

原机器更换 IP 后，转发规则一般无需删除，因为监听端口仍在同一机器，目标落地也未变化。在“服务器列表 → 配置”的 SSH 区域填写新 IP / 域名（必要时修改 SSH 端口 / 用户名），勾选“同机换址，保留转发规则”，保存即可。密码未变可以留空保留，不要勾选清除密码。

主控会连接新地址，使用已保存的原 SSH 指纹验证主机密钥，并执行固定只读 Python 检查：共享引擎 state 的 owner 必须等于节点 ID；若没有引擎 state，则核验新 / 旧采集端配置中 token 的 SHA256 与原节点一致。有引擎 state 却归属不同，不能用采集 token 绕过。不会输出远端密码 / 配置，不修改远端文件、不安装或重启服务。

连接失败、密码错误、主机密钥不同、节点归属不符、无 Python 或权限不足时不保存新配置；核验期间其他部署 / 修改被拒绝，配置变化或备份恢复后不会覆盖旧快照。验证成功保留原 SSH 指纹、规则 ID、网卡与转发历史、采集密钥；普通未勾选换址仍保留原保护。

此功能仅为同一台机器修改管理连接地址，不迁移服务到另一台机器，也不自动部署 / 恢复配置。重装系统导致密钥或节点配置改变时，应重新确认机器和迁移方案，不能直接跳过身份验证。

客户端要改用新入口 IP；其他入口 / 中转机器规则内引用旧地址的地方也需手动改动，按原编辑流程可能重部署并清空相应规则历史。主控仅更新该节点的 SSH 地址，不批量改写目标地址。使用域名时，应先更新 DNS，确保主控能解析并连接新地址。自动国家识别依赖新上报，手动国旗不改。

## 同机换址提示指纹不匹配（v0.2.48）

只换 IP 通常不改变 SSH 主机密钥；收到不匹配提示时，先确认地址是否正确、是否重装或重生成 SSH 密钥。旧版测试成功不会更新同机换址保存所用的指纹；v0.2.48 已接通此流程。

勾选“同机换址，保留转发规则”，点击“测试 SSH”。新指纹不受信时需通过 VPS 控制台核对后确认，不能仅凭页面显示就信任。测试在新 SSH 连接下执行原节点身份验证；新指纹与旧指纹不同时，除已有引擎归属检查外，还必须核对远端原采集端配置 Token 的哈希，不能仅凭节点编号验证。

核验成功后两分钟内保存；证明绑定当前登录会话、节点、SSH 连接字段、密码和原配置，一次有效。保存再次连接并验证身份，才更新新地址和新指纹。字段更改、关窗、过期或主控重启后需重新测试。未完成核验时原配置、规则和历史保留；服务不重启。此流程允许明确核对过的新密钥，替代上文 v0.2.47 仅接受原指纹的限制，不提供自动忽略 SSH 指纹的方法。

## Metrics 长期读取失败或流量不更新（v0.2.49 / 采集端 0.2.6）

一次现场检查：HTTP 200、响应 14,418,400 字节、最长行 192 字节、读取耗时 0.722 秒。该样本没有超长行，但规模较大；旧采集端的两秒 HTTP 总限时包含读取和解析耗时，低性能或高负载时可能触发失败。单次快速下载不能排除其他轮次的超时、中断或解析问题，不能直接据此断定统计数据本身有错。

先更新主控，再在“服务器列表”更新受影响机器的采集端到 0.2.6；不要误点转发管理中的安装 / 更新。更新采集端不重启 GOST。等待约一分钟，查看转发采样是否恢复。若仍失败，复制新的具体错误与 /opt/firefly-probe/agent --version 结果继续核查。

0.2.6 使用更快的逐行指标 / 服务标签解析；每个 Metrics 地址单次读取，最多四个地址并发，单次 12 秒、整轮 15 秒，按 64 MiB 总量 / 64 KiB 单行限制流式处理。完整读取后才接受该端点样本，超时、中断、无效值、超上限或清单变化不提交部分计数。与以前相比，“超时”“单行过长”“读取中断”分别提示。

后台采集同一时刻只运行一轮，不阻塞基础监控上报，每 30 秒最多发起一轮。第一轮结果随后续上报送达，通常一分钟内可见；慢响应不会拖住主循环。旧版 0.2.5 仍兼容，但不具备此次修复。

失败期间保留旧基线，仍在同一 GOST 进程、同一规则代次且累计数未重置时，恢复后会补计累计差额，重复上报不重计；无法精确还原跨日缺失数据，已丢失 / 重启清空的原始计数不能补回。64 MiB 不是无限容量，达到上限仍拒收；诊断工具、迁移 / 操作时的 Python 最终快照另有原先的读取限制，此次未自动重启或改写 GOST 的指标配置。

## 更换或取消中转（v0.2.50）

在入口规则操作区点击“经中转”。已通过面板完成的中转，会显示当前 A → B → C 路径和以下操作：

- 更换中转：选择新服务器或调整中转监听端口，先“安装 / 检查新中转”，成功后确认切换入口。C 使用原任务记录的落地地址，A 的入口端口与协议不变。也可重新使用原 B 上完全相同且运行中的规则。
- 取消中转，恢复直连：确认后将 A 的目标恢复为 C；无需连接旧 B，即使 B 离线或 B 规则已删除也可操作。A 仍需已配置 SSH、确认指纹且可连接。

两种操作都沿用现有编辑部署逻辑：入口会短暂断流，成功后该入口规则生成新 ID，其转发月累计及每日历史清空；仪表盘的服务器网卡流量历史不受影响。旧中转规则及其历史保留，不会自动停止或删除，因为它可能还被其他入口使用；不再需要时到旧服务器单独停止 / 删除。

更换失败、放弃第 2 步均不改变原入口路径；入口重部署失败会尝试恢复旧配置，请核对日志及实际连通性。已有任务未结束时不能并发更换或取消；关闭窗口不会取消远端操作，重新打开可继续查看。完成后也可再次调整。

兼容升级前保存的成功中转任务；手动搭建且没有面板中转记录的链路无法推断原落地地址，请编辑入口规则。上述操作不自动清理旧 B，不构建多级中转链，也不将服务启动视为端到端连通保证。本节替代 v0.2.44 中暂不支持快捷回退的限制。

## 共享引擎提示 Metrics 超过 16 MiB（v0.2.51）

采集端 0.2.6 的日常流量上报已支持 64 MiB，但旧主控的切换前最终快照仍限 16 MiB，因此可能出现日常上报正常、停止 / 更新 / 编辑规则却被拒绝。该快照用于服务改变前保存最后累计计数，不能简单跳过。

更新主控到 v0.2.51 后重试原操作即可。主控每次执行共享操作都会下发新版控制器，无需手动修改 VPS 文件，也无需为此升级采集端或重启整个共享引擎。原操作若是停止 / 更新 / 编辑，仍会产生其本来预期的服务变化；更新主控本身不修改转发规则。

最终快照现在按流读取，最多 64 MiB，单行最多 64 KiB；不保存整份响应，减少小内存 VPS 的额外开销。连接 / 单次阻塞读取超时 5 秒，读取过程中检查 15 秒截止时间（阻塞读取最多可能再等待一个读取超时）。响应声明长度不完整、超限、无效计数、缺少标记或采样期间清单变化时不输出部分最终计数，并阻止继续修改规则。

64 MiB 仍为有限上限，超过时需检查指标规模；本版不通过重启 GOST 清空计数来绕过错误。GOST 管理 API 响应独立保留 16 MiB 限制，诊断脚本也仍使用原读取限制。本节补充 v0.2.49 当时未升级的 Python 最终快照路径；原有历史归日方式不变。

## 无运行规则时提示 TypeError（v0.2.52）

GOST 在没有服务时可能返回 {"count":0,"list":null}，旧控制器有几处直接遍历 list，导致 TypeError。检查状态、删除服务及失败恢复都使用服务列表，这个错误也可能掩盖更早的安装失败原因。

更新主控后，控制器统一识别数量为 0 的空列表；全部规则停止后可再次安装 / 更新。列表格式异常、数量不一致不会当成正常空列表，安装后仍必须确认新服务确实出现在 API 中。遇到其他错误会显示内部函数与行号，HTTP 错误另附状态码，不显示原始异常内容或凭据。

只需更新主控，再重试失败的操作；新控制器会随操作下发，采集端仍为 0.2.6，无需因此重新安装采集端或手动删除现有规则。此次修复已在本地复现空列表路径；现场一键安装 / 更新是否还有其他失败原因，需要更新后实际确认。采样、规则标识及编辑清空流量的原有约定不变。

## 批量删除转发配置（v0.2.53）

转发管理右上角“批量删除”打开当前服务器 / 分组的规则清单，包含其他分页和状态中的规则。默认不勾选，支持全选 / 全不选；确认框显示选中数量，提交后逐条删除，并展示成功、失败、跳过与日志。关闭进度窗口不会停止队列。

已部署规则沿用单条删除流程：连接该服务器、停止并删除远端对应规则，再删除主控配置及该规则转发流量历史。未安装且没有部署任务的草稿只删除主控配置，不要求 SSH。缺少 SSH / 指纹或停用的服务器会跳过，操作失败的配置保留供检查重试。主控重启中断队列后不会自动继续，需核对列表和日志再提交。

规则与转发历史删除无法撤销，重新添加后重新统计；服务器节点及仪表盘网卡历史保留。关联入口中引用的旧转发地址不会自动改写，请按实际链路处理。安装 / 更新与批量删除共用互斥队列，不能并发执行。

本功能不清理其他面板或手动部署的 GOST。2026-11-09 用户日志中，多个 gost 进程占用 443/446/2053/53790 等端口，萤火共享 gost-3.3.0 另有进程；仅删除并重新添加萤火配置不会释放这些外部占用，需先确认旧服务归属并停用对应旧服务，不能直接批量杀掉全部 GOST。

## VPS 重装后重新部署（v0.2.54）

VPS 重装会清除远端配置，但主控数据库仍可能保留“已部署 / 共享模式”的记录。旧版继续读取 /etc/firefly-forward-engine/state.json 时会报 FileNotFoundError；这条错误表示文件缺失，不能据此判断端口被占用，重装前的端口诊断不能代表重装后状态。

先在服务器列表安装采集端，并完成 SSH 配置及指纹核对，再在转发管理安装 / 更新规则。v0.2.54 在标准规则操作中检查状态文件：若远端没有引擎配置 / 迁移记录 / 统计清单、没有运行的共享服务及遗留独立转发部署，会重新初始化共享引擎，只启动当前选中的规则；“一键安装 / 更新”继续按队列逐条恢复。其他旧规则先标记停止，主控已保存的转发历史不清零，丢失的远端原始计数不能恢复。编辑规则仍遵循编辑成功后清空该规则历史的约定。

若 state 缺失但 config / 迁移记录仍在、共享服务仍运行，或检测到独立规则文件 / 服务，拒绝作为空机器直接覆盖；需要先核对实际部署。原有独立部署的首次迁移仍走原迁移检查与备份流程，不借此强制清理旧进程。其他程序占用端口时不会自动终止，仍会报真实安装错误。

远端确认完全为空后，检查状态 / 停止返回未部署结果；删除只移除主控选中配置及相应转发历史，不启动引擎。只需升级主控，采集端仍为 0.2.6；重装后的采集端如尚未重新接入，应先完成接入。SSH 指纹变化仍需管理员核对，不跳过身份验证。
