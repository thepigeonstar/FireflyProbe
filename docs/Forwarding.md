# TCP / UDP 转发

主控左侧的“转发”页面用于管理服务器上的独立 GOST 服务。数据直接经过所选服务器，主控仅通过 SSH 下发配置，不承载转发流量。

1. 在服务器列表填写 SSH 地址、端口、用户名和密码，测试连接并确认服务器指纹。需要 root 或免密 sudo。
2. 在“转发”添加规则，选择服务器、协议、监听端口、目标 IP/域名及端口。
3. 保存后点击“安装”或“更新”，查看日志；停止会取消开机启动，删除会停止并移除对应服务。

例如监听 10161、目标 149.7.2.22:8443、协议 TCP + UDP，生成：

```text
tcp://:10161/149.7.2.22:8443
udp://:10161/149.7.2.22:8443
```

监听所有网卡，未提供加密和客户端身份认证。按实际需要在服务器防火墙、云安全组或 NAT 端口映射中允许对应协议及来源。程序不自动调整防火墙，也不改动已有 GOST 安装。

首版支持 amd64 / arm64，使用 systemd 的 Debian 11+、Ubuntu 22.04+，以及使用 OpenRC 的 Alpine 3.20+。先安装采集端以准备 curl、Python 和系统工具。GOST 固定使用官方 3.3.0 发布文件，下载后按主控内置的官方 SHA256 校验。远程服务器需要能访问 GitHub。安装路径 `/opt/firefly-forward/gost-3.3.0`；每条规则对应 `firefly-forward-规则UUID` 服务。目标支持 IP、IPv6 和域名；监听范围使用 GOST 默认行为，按所有网络接口开放。

状态显示最近一次 SSH 操作的检查结果，点击“检查状态”获取实时服务状态。服务运行不保证目标可达；检查目标服务和防火墙。主控重启后远端服务继续运行。规则配置随主控数据库备份，恢复备份不会自动操作远端服务，需核对状态和遗留规则。停止/删除失败会保留规则，避免将仍在运行的服务隐藏；删除节点或更换 SSH 地址前需先移除转发规则。重新创建同名服务器不会接管旧 UUID 的服务。

手动诊断：`systemctl status firefly-forward-规则UUID --no-pager` 或 `rc-service firefly-forward-规则UUID status`。systemd 日志：`journalctl -u firefly-forward-规则UUID -n 50 --no-pager`。

本功能不依赖插件页面授权，只有登录管理员可操作，写接口需要 CSRF。插件未获得转发接口权限。

GOST 的规则格式参考：[官方命令行文档](https://gost.run/reference/configuration/cmd/)。

## 流量与状态

从 v0.2.18 起，采集端 0.2.2 每 30 秒读取由主控安装的 GOST Metrics。首次使用需要更新采集端，并对已有规则重新点击“安装”或“更新”；会重启该规则的连接。Metrics 只监听 127.0.0.1 的独立端口，不开放管理 API。每次进程启动生成新的统计标识，避免累计计数归零后漏算或重复累计。

每条规则显示 GOST 接收、发送和合计流量，按主控时区的自然月划分，历史保留最近 24 个月。月初切换新月显示，旧月不会删除。主控备份包含规则、计数基线和月份历史。删除规则会删除该规则的流量历史。统计为 GOST 处理字节，不等同于 VPS 网卡计费。无法补录启用前的流量；停止、进程崩溃或跨月时可能存在一个采样间隔的偏差，主控长期离线后的累计按恢复采样时归属月份，不适用于精确跨月对账。

状态灯显示最近的观测结果：绿色表示最近收到实际转发流量；红色表示 SSH 操作失败或采集到 GOST 转发错误；黄色表示服务运行但尚无近期流量验证。未发起请求时，不能据此确认 UDP 目标可达。日志在弹窗内自动更新。

## 每日明细

v0.2.19 将转发地址和流量拆成独立列。列表显示当前自然月累计，点击流量后选择月份查看每日接收、发送和合计，按主控统计时区划日。没有样本的日期不伪造为零流量；升级前仅保存月累计的部分以“升级前未分日”标明。采集端保持 0.2.2，不需要再次更新。

“服务运行 · 待验证”表示服务已启动，但尚未收到近期真实流量验证。通过该规则的入口 IP/端口，使用对应业务客户端发起请求；采集端约每 30 秒采样。只有观察到 GOST 收发字节增量，且近期没有新错误，才会显示绿色转发成功；错误增量会显示红色转发失败。检查状态只检查服务进程，不主动产生业务流量。5 分钟没有新的流量验证，或统计样本超过 90 秒未更新，会回到待验证，不代表服务必然故障。TCP + UDP 合并规则的灯表示汇总观测结果，不能单独证明两个协议或最终业务都可用。

## 规则排序

v0.2.20 支持拖动规则左侧手柄排序，或聚焦手柄后用上下方向键调整。排序按所选服务器独立保存，不重启 GOST，也不改变规则入口或流量记录。

## 编辑并重新部署

v0.2.21 在规则操作中增加“编辑”。可以修改名称、协议、监听端口和目标地址；服务器保持不变。提交前会提示连接中断和流量清零。修改以新服务标识部署，成功后移除原服务，清空该规则的月份、每日历史和统计基线，并保持原排序。旧服务的缓存样本不会重新计入新规则。

部署失败保留原配置和历史，并尝试清理新服务、恢复原服务；恢复也失败时日志会明确说明，需核对服务器状态。中断或失败任务可重新编辑部署或删除规则，重试时会清理上次候选服务。SSH 任务进行中不允许重复编辑。编辑其他服务器需创建新规则。采集端保持 0.2.2。

## 安装、更新与启动按钮

v0.2.22：尚未安装显示“安装”，已安装显示“更新”，更新会重新应用主控提供的 GOST 版本及规则配置并短暂重启连接，不清空流量。运行中显示“停止”，停止后该按钮切换为“启动”；启动沿用现有服务，不重新下载或改写规则。编辑后重新部署仍会清空该规则的历史。编辑日志通过步骤 1/3、2/3、3/3 区分停止原服务、启动新服务、删除原服务文件，最后确认新服务运行。

## 全部转发流量汇总

转发页面顶部显示今日、昨日的全部规则收发合计，单位固定为 GiB，保留两位小数。按主控统计时区的自然日汇总所有服务器，切换服务器不影响汇总；停止的规则仍计入当日已采集流量。数据随采集端上报更新。只有月累计的旧数据不能补算日流量，删除规则或编辑成功清零后，该规则原历史也不再计入汇总。

操作按钮采用图标，鼠标悬停或键盘聚焦显示名称，删除置于最右侧；安装后显示更新，停止后显示启动。“服务运行”表示服务已启动，绿色“转发成功”仍以实际采集到转发流量为依据。
