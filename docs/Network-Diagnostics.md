# TCP 可达性快速判断

先从大陆三网与海外多个测点测试同一 IP、同一端口，再检查服务、抓包；避免先反复重装或修改规则。ITDOG 在线 TCPing 提供国内运营商与港澳台、海外测点选择：https://www.itdog.cn/tcping/ 。网页默认展示和其他人的结果不能作为自己的目标检测报告，需要输入目标执行本次测试。

## Windows 一次命令对照

下载 tools/network-diagnose.ps1 到电脑。使用 Windows PowerShell 5.1 或更高版本，OpenSSH 客户端可用。电脑为大陆网络，RemoteHost 选择一台可以 SSH 登录的境外 VPS（需要 Python 3，萤火采集端支持的机器已有此依赖）。脚本不会自动识别所在地；不要把香港或境外主控当作大陆测点。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\network-diagnose.ps1" -TargetIP "91.110.231.133" -PortList "1443,11443" -RemoteHost "境外VPS的IP"
```

RemoteHost 请替换为实际可登录的境外 VPS 地址；SSH 默认用户 root、端口 22，可用 -RemoteUser 和 -SSHPort 修改。首次连接按 SSH 正常流程核对主机指纹，密码直接输入 SSH 提示，脚本不保存密码，不修改 SSH 全局配置。

执行前关闭 Clash TUN 并退出代理，确保测的是当前网络。每个端口默认尝试 3 次，每次最多 3 秒；仅连接并关闭，不发送业务数据，不改防火墙、规则、服务，不清除流量。最多检查 8 个端口，禁止使用全端口扫描来替代有效对照。

只有已确认监听的端口才有比较意义。SSH、业务、备用端口可选不同用途的端口，但先确保远端来源可连且服务正常；未监听端口超时不能证明被阻断。可加 -OutputFile 指定 JSON 报告位置，否则保存在当前目录，文件名含检测时间。报告包含 IP / 测点地址与结果，无 SSH 密码或 Token。TCP 成功仅表示连接建立，不证明目标业务或 GOST 整条链路可用。

## 解释结果

| 现象 | 判断范围 |
| --- | --- |
| 本机与远端都成功 | 本轮两处 TCP 可达，业务问题另查协议与落地 |
| 一个端口本机超时、远端成功，其他端口两边成功 | 疑似端口或路径相关差异，查访问策略与防火墙 |
| 多个已开放端口本机均超时、远端均成功 | 疑似来源网络相关 TCP 受限；若所在地分别是大陆和境外，则符合国内到该 IP 的多个 TCP 端口受限的表现 |
| 仅部分尝试成功 | 连接不稳定，需更多时段和测点 |
| 两边都失败 | 优先确认目标监听、防火墙、目标与测点网络；不能直接判断阻断 |
| 连接被拒绝 | 与超时分开，通常是主动拒绝 / 监听或策略问题，不能直接当作静默丢包 |
| SSH 或远端 Python 检测失败 | 测点不可用 / 检测未完成，不是目标被阻断 |

单台电脑与单台 VPS 不代表全国、所有运营商或所有端口。小样本无法证明全部 65535 个端口不可达，也无法单凭 TCP 超时确定由 GFW 导致。需要更多省份 / 运营商 / 不同时段交叉验证，并让商家核对清洗、回程与访问策略。Ping 成功也不能证明 TCP 成功。

## 集成探针的边界

本次交付为独立诊断脚本，当前面板没有新增自动监测或通知。若以后集成，应配置真实中国大陆测点与境外测点，或接入有文档和凭据的多点检测服务；仅在境外主控发起连接，无法判断大陆用户可达性。

持续告警应保存每个来源的网络类别、端口、成功率、错误、时间与测点自身健康。连续多轮确认异常后提醒，恢复也经多轮确认，避免瞬时抖动误报。建议显示“国内 TCP 可达性异常”“部分端口受限”“测点异常”等结论，不把未验证原因写成“GFW 已封锁”。服务正常但无用户连接时，也不能只按流量下降判定被阻断。
